# Laver Cup Migration Decision Record

## Decision target

Decide what should graduate into COURT after the Qualifying Draw, Australian
Open, Roland-Garros, Wimbledon, US Open, and Davis Cup phases.

## Evidence

| Surface | Evidence | Result |
|---|---|---|
| COURT core | `court-core` tests cover identity, action availability, snapshot metadata, scene intent, adapter hints, and validation evidence records. | Contract shape is ready for additional fixtures. |
| RACKET adapter | `racket-core` tests consume COURT snapshots and emit diagnostics for unsupported actions, scene roles/features, and provenance boundaries. | Adapter diagnostics are ready; runtime loop is not yet proven. |
| AMAZE product fixture | `prism_vault_court_snapshot()` and `prism_vault_court_validation_packet()` sit beside `prism_vault_muddle_host()`. | First product slice proves COURT adoption without replacing MUDDLE. |
| MUDDLE path | Existing AMAZE Prism Vault MUDDLE tests still validate the playable command path. | MUDDLE remains the working runtime/client path. |
| RALLY substrate | RALLY remains referenced for deterministic validation and report-shape lessons. | No RALLY runtime migration is approved in this wave. |

## Graduation decisions

| Capability | Decision | Rationale |
|---|---|---|
| Experience identity | Graduate into COURT. | Product-neutral and already consumed by RACKET/AMAZE. |
| Action availability labels and states | Graduate into COURT. | Describes affordance shape without executing product policy. |
| Snapshot metadata | Graduate into COURT. | Needed by adapters and fixtures to compare experience version/surface/scene contract. |
| Scene roles and UX intent | Graduate into COURT. | Product meaning and player-read labels are portable across MUDDLE/RACKET surfaces. |
| Provenance classes | Graduate into COURT. | Source custody boundary is framework-level and adapter-visible. |
| Adapter diagnostics | Keep in RACKET, shaped by COURT. | Diagnostics are engine-adapter behavior; COURT owns the input contract. |
| Playtest/assessment evidence shape | Graduate into COURT as references only. | Product-neutral record shape is reusable; player details and scripts stay product-owned. |
| MUDDLE room-command runtime | Keep in MUDDLE. | It is the working playable path and should not move during foundation. |
| MUDDLE browser/native clients | Keep in MUDDLE. | COURT has no client/runtime responsibility yet. |
| MUDDLE checkpoint persistence | Keep in MUDDLE/product hosts. | COURT snapshots describe experience handoff, not persistence storage. |
| RALLY seeded runs and metrics | Keep in RALLY. | Deterministic simulation and comparison reports are substrate capabilities. |
| RALLY validation findings | Reference from COURT evidence records. | COURT can point to evidence shape; RALLY owns run/report production. |
| Product rules and puzzle logic | Keep in product repos. | COURT and RACKET must not infer or execute game-specific rules. |

## Maturity gates

| Layer | Status | Next gate |
|---|---|---|
| Identity/action/provenance | Ready for a second product fixture. | Add another product slice without weakening existing tests. |
| Snapshot/scene intent | Ready for fixture expansion. | Map a MUDDLE visual-node-rich slice and compare adapter diagnostics. |
| RACKET adapter diagnostics | Ready for non-window smoke checks. | Add a runtime loop only after diagnostics stay explicit. |
| Playtest/assessment records | Ready as reference records. | Connect to a product-owned playtest script or RALLY evidence packet by reference only. |
| Product migration | Not approved. | Require two product fixtures and one adapter beyond static frame plans. |

## Decision

Laver Cup approves COURT as a portable contract framework for additional
fixtures. It does not approve moving MUDDLE runtime/client behavior, RALLY
simulation/report behavior, or product rules into COURT.

Next implementation should add a second product fixture or a RACKET runtime-loop
spike only if it preserves the same boundary: product repos own rules, MUDDLE
stays playable, RALLY stays deterministic, COURT stays portable, and RACKET
reports unsupported features explicitly.
